## 三、4 种采集方法（候选）

propose 了四种方法。详细评估留到 § 五。

### A · 模板帖关键词搜

按"求讨论"句式搜帖：`"怎么看 XX"` / `"XX 还能上车吗"` / `"XX 该不该买"` / `"XX 值不值得抄底"` 等。模板帖天然吸引情绪化评论，标题正则可匹配，不用 LLM 分类。

**主要风险**：模板帖本身互动可能一般（不是爆款）；句式池要定期 review 新词。

### B · 爆款帖评论 ticker tagging

**核心反转：用帖子覆盖关键词，不是用关键词找帖子。** A/C 都是 ticker → 帖子，B 是帖子 → ticker。挑 `n_likes ≥ 1000` 的情绪化股票帖，抓全量评论（500+ 条），逐条 LLM 抽 ticker。单帖能产 100+ 条 ticker-tagged 评论。详见 `docs/m1_viral_post_tagging_spike.md`。

**主要风险**：supply 不稳（爆款可遇不可求）；爆款帖访问量大可能被风控盯（BLUEPRINT § 八 风险 6）。

### C · KOL 关注列表（备份）

不按 keyword 搜，按"作者"拉。手动挑 5-10 个股票垂类 KOL，xhs-mcp 按 user_id 拉他们最近 7 天发的所有帖。

**主要风险**：sample bias 大（KOL 选谁就定调），需多空对冲选 KOL；KOL 自己也会被限流。

### D · DIY 自发帖

副号自发"怎么看 XXX"，第二天收评论 → 落盘 → 删帖。100% supply 可控。

**主要风险**：XHS 反作弊高风险（发-删模式显眼）；账号被封 = 同时挂掉 ManualScraper 兜底；合规边缘。

## 四、初步规律 / 筛选规则

4 个方法要跑起来，得先给它们喂"种子"——句式池、关键词、黑名单、阈值。下面这些是当前的初步直觉，**全部待 § 五 案例研究验证**。

### 4.1 Pattern / 关键词 / Q 句式（喂方法 A/B/C 的种子）

- **方案 A 句式池**（用来正则匹配标题）：
  - `怎么看 XX` / `XX 还能上车吗` / `XX 该不该买`
  - `XX 值不值得抄底` / `XX 还能拿吗` / `求大佬指点 XX`
  - `XX 还有救吗` / `XX 能不能看` / `XX 还能不能买`
- **方案 B 爆款帖筛词**：
  - 互动门槛：`n_likes ≥ 1000`
  - 内容相关：含股票/A股/美股/港股/基金/牛市/熊市/抄底/梭哈/被套等
  - 情绪信号：感叹号密度、晒持仓截图、短句
- **方案 C 候选 KOL 名单**：5-10 个股票垂类账号，待群里挑（含多空对冲）

### 4.2 财报分析贴排除黑名单（粗筛词）

候选词（待 § 五 案例研究标注"否"样本里反推确认）：

- **财报基本面**：财报 / 营收 / 业绩 / 季报 / 年报 / 财报解读
- **估值指标**：PE / PB / 估值 / 现金流 / 毛利率 / 拆解 / DCF
- **技术分析**：K 线 / 均线 / MACD / 支撑位 / 阻力位 / 趋势线
- **卖方研报**：卖方 / 研报 / 目标价 / 评级

### 4.3 时间敞口约束

| 时间敞口 | 例子 | 是否保留 |
|---|---|---|
| 短（小时-日） | "今天又跌了，想哭" | ✅ 要 |
| 中（本周） | "这周财报前梭哈了一手" | ✅ 要 |
| 长（财报季 / 半年展望） | "NVDA 明年估值能看到 X 倍" | ⚠️ 边界（见下） |

> **长敞口的边界**：估值建模式陈述（PE/DCF/分部估值拆解）剔除；情绪式展望（"梭哈到年底"/"明年翻倍"/"年底见 200"）保留——后者本质是顶部 FOMO 的长周期变体。具体边界待 § 五 标注后定。

### 4.4 情绪强度门槛

初步方向（待 § 五 标注后定阈值）：

- 弱(1)：陈述性语气、无明显情绪信号 → **不要**
- 中(2)：有情绪倾向但表达克制 → **要**
- 强(3)：感叹号密集、极端字眼（梭哈/暴富/血亏/跑路） → **要**

### 6.1 4 种采集方法 A/B/C/D 你给个排序

最值得先跑的 → 最不值得的，给个排序。理由欢迎一并写。

我自己的倾向（仅供参考）：
- A 模板帖 ★★★（最先跑，句式池可正则、风险低）
- B 爆款帖评论 ticker tagging ★★★（核心反转 + 数据密度最高；supply 不稳是次要风险）
- D DIY 自发帖 ★★（supply 100% 可控，唯一一个不靠外部供给；需配合副号 + 不删帖管理反作弊）
- C KOL 关注列表 ★（备份，sample bias 重 + KOL 自己也会被限流，仅前三都失败启用）

### 6.2 `is_emotional` 门控放 M1 还是 M2

**真实 gap**：M1 召回里混了大量财报 / 估值 / 技术分析贴（§ 4.2 黑名单想排的就是这类），不过滤会糊后续聚合。需要一个 `is_emotional` 门控判"这帖是否情绪化"——§ 4.2 的黑名单粗筛只是其中一种实现。

放哪一层：

| 实现 | 模块归属 | 代价 |
|---|---|---|
| M1 正则/启发式粗筛 | 纯 M1 | 准确率有限，但不动 M2 prompt |
| M2 prompt 加 `is_emotional` 字段 | M2 主导 | 改 `config/prompts.yaml` → 走 CODEOWNERS |
| 混合：M1 粗筛 + M2 细判 | 跨 M1/M2 | M1 先排明显的，M2 微调 prompt |

我倾向 M1 粗筛（自包含、省 LLM 成本、不走 CODEOWNERS）。直接 M2 prompt 加字段会不会更简单？

### 6.3 方案 C（KOL）保不保留为备份

我倾向保留：手动维护 5-10 个多空对冲的 KOL，仅前三方案 supply 都不够时启用，运维成本低。

直接 ban 掉也行——sample bias + 选谁定调 + KOL 自己被限流，三个风险叠加，作为备份的可靠性打折。
